# 任务规划技能

按以下两层次进行任务规划。

## 第一层：宏观规划

将任务拆解为若干个宏观阶段。

1. 根据任务目标给出宏观规划，将任务分解为逻辑上独立、可逐次执行的阶段
2. 输出 JSON，**必须严格符合知识库参考中注入的 `macro_plan.json` schema 定义**。用 ```json 代码块包裹，禁止调任何工具。
3. 阶段划分要合理，覆盖任务全流程。每个阶段有明确的独立目标
4. 输出后询问用户"是否确认以上宏观规划方案"

## 第二层：详细规划

用户确认宏观规划后，系统会逐阶段对每个宏观阶段进行详细规划。每次只处理一个阶段。

1. 每次调用时，你会收到一个具体的宏观阶段（含阶段ID、名称、目标），请只对该阶段进行拆分
2. 将该阶段拆解为若干个原子动作，每个原子动作代表一个不可再分的执行步骤。动作数量要尽量少：多个连续物理动作合并为一个，系统自动完成的校验记录合并为一个。
3. 输出 JSON，**必须严格符合知识库参考中注入的 `atomic_action.json` schema 定义**。actions 数组中只包含当前阶段的原子动作
4. 每个原子动作的 executor **必须且只能是 `tool`**：调用算法工具执行计算。
   不调用工具的步骤不生成原子动作。
5. **当 executor 为 tool 时：**
    - `tool_name` 必须是知识库参考中「已注册算法工具列表」里的工具名称之一，禁止使用不存在的工具名
    - `tool_inputs` 必须严格按该工具在 `input_schema` 中定义的参数名提供，禁止自定义参数名
    - **必填字段 `post_action_update`**：一条自然语言指令，描述该动作执行后需要更新 Redis 中的什么信息。**必须指明要更新的具体对象（用 UAV_ID/target_ID，如 UAV_1、T1）**。不要写具体值，只写语义描述。执行时会自动根据该指令、goal 和已解析的参数值决定更新内容。
      - 示例：规划去程后 → `post_action_update: "将UAV_1的当前位置更新为目标T1的位置坐标"`
      - 示例：规划返航后 → `post_action_update: "将UAV_1的当前位置更新为起飞点坐标"`
      - 示例：锁定目标 → `post_action_update: "将目标T1的状态更新为已锁定"`
7. **工具的选择与适用动作，以本次对话知识库参考中注入的「已注册算法工具列表」和「原子动作执行器类型说明」为权威依据。** 每个阶段只生成能在工具列表中找到对应算法的动作；没有对应算法的步骤（如自检、数据归档）不生成原子动作。
8. 详细规划阶段禁止调用任何工具
9. 当前阶段拆分完成后，等待系统自动注入下一个阶段继续拆分
10. 每个原子动作必须包含 `goal` 字段。goal 只写语义描述，不要写具体坐标或数值（具体值由执行时从上下文中查找）。
    - **tool 动作的 goal 必须明确写出各参数的语义来源**，格式为"以X为参数A，以Y为参数B，做某事"。**必须用 UAV_ID 和 target_ID 指明是哪个对象**，否则执行时无法区分多架 UAV/多个目标。例如：
      - goal: "以UAV_1的当前位置为起点，以目标T1的位置坐标为终点，规划航线"（起点=UAV_1的当前位置，终点=目标T1）
      - goal: "以UAV_1的当前位置为起点，以base的起飞点坐标为终点，规划返航航线"（起点=UAV_1的当前位置，终点=base起飞点）
      - ❌ 错误示例：goal: "以当前位置为起点，以目标位置1为终点，规划航线"（没有 UAV_ID，有多架 UAV 时无法匹配）
      - ❌ 错误示例：goal: "从当前位置到目标位置"（没有指定具体对象，对应关系不明确）
