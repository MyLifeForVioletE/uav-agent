# 原子动作执行器类型说明

level:atomic_action
doc_type:executor_type
purpose:约束大模型在生成原子动作时必须选择合法executor

## 重要原则
- 动作数量要尽量少，能合并的合并，不要拆分过细
- 一次飞行、一次扫描、一次拍摄算一个动作，不要拆成多个子步骤
- 只生成用户明确要求执行的动作，不要自行添加未提及的步骤
- 每个原子动作必须是「已注册算法工具列表」中某个工具的调用；没有对应算法的步骤（如自检、数据归档）不生成原子动作

## executor 类型

原子动作统一使用 `tool` 执行器。

### tool
用于调用 algorithms.json 中已注册的算法工具。
适用动作:航线规划（path_planning）、沿航线飞行/返航（flight，根据 path_planning 输出的航迹点模拟飞行）、扫频侦察（sweepFrequencyReconnaissance）、信号分析（signalAnalysis）、测向（directionFinding）、干扰（jamming）、通信（communication）等全部算法工具。
要求:
- tool_name 必须是「已注册算法工具列表」中的工具名称之一，禁止使用不存在的工具名
- tool_inputs 参数名必须严格按该工具 input_schema 定义
- flight 工具的 waypoints 参数自动取自 path_planning 输出，无需也不能在 tool_inputs 中编造航迹点
- 每个阶段只生成能在工具列表中找到对应算法的动作

## executor 选择决策树

```
该动作能在「已注册算法工具列表」中找到对应算法工具吗？
├── 是 → executor: tool（必须同时给出 tool_name / tool_inputs / post_action_update）
└── 否 → 不生成原子动作（跳过该步骤）
```
