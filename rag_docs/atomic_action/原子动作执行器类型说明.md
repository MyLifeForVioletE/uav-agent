# 原子动作执行器类型说明

level:atomic_action
doc_type:executor_type
purpose:约束大模型在生成原子动作时必须选择合法executor

## 重要原则
- 动作数量要尽量少，能合并的合并，不要拆分过细
- 一次飞行、一次扫描、一次拍摄算一个动作，不要拆成多个子步骤
- 只生成用户明确要求执行的动作，不要自行添加未提及的步骤

## executor类型

### tool
用于调用 algorithms.json 中已注册的算法工具。
适用动作:航线规划（path_planning）。
要求:tool_name 必须是已注册工具之一，tool_inputs 参数名必须严格按 input_schema 定义。

### external
用于无人机硬件实际执行的物理动作。
适用动作:起飞、降落、沿航线飞行、开启/关闭载荷、拍摄、悬停。
要求:多个连续物理动作（如起飞+爬升+调整姿态）应合并为一个动作。

### system
用于系统内部软件操作和数据记录。
适用动作:保存航线、记录日志、数据归档、航线校验。
要求:能自动完成的校验、记录类操作归为 system，不要拆分成多个独立动作。

## executor 选择决策树

```
该动作需要无人机硬件执行吗？
├── 是 → external
└── 否 → 这是调用 algorithms.json 中注册的算法工具吗？
    ├── 是 → tool
    └── 否 → system
```
