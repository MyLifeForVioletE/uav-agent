============================================================
UAV Agent 多机协同规划系统 —— HTTP 接口文档
============================================================

服务地址：http://192.168.6.11:8000
启动命令：python -m uvicorn http_server:app --host 0.0.0.0 --port 8000

说明：
1. 本服务为"无确认自动模式"：提交任务描述后自动完成
   参数收集 → 任务分解 → 任务分配 → 详细规划 → 多机协同执行 全部流程，
   全程不需要用户确认或补充输入。
2. /api/run 直接返回动作脚本和异常应对的完整 JSON 数据。
3. 前置依赖：Redis、Kafka、Ollama 需已启动。

------------------------------------------------------------
接口 1：提交任务（执行整个协同流程）
------------------------------------------------------------
POST /api/run

请求头：Content-Type: application/json

请求体（JSON）：
{
  "scenario": "任务描述文本"
}

字段说明：
  scenario (string, 必填)：用户输入的任务描述

请求示例：
curl -X POST http://192.168.6.11:8000/api/run -H "Content-Type: application/json" -d "{\"scenario\":\"现在有一个任务，使用一架侦察无人机到位置1侦察敌方的一个通信目标。期望得到敌方通信目标的频率、带宽、信号强度信息。该目标通信使用的频率在2~3GHz，步进为500。无人机现在处于基地，基地位置在70，15，目标位置在70，15.01 \"}"

响应（JSON，HTTP 200）：
{
  "actions": {
    "steps": [
      {
        "step_id": "agent1-1",
        "subject_id": "agent1",
        "step_type": "sweep_frequency",
        "step_name": "频谱扫描",
        "input": {"start_freq": "2GHz", "end_freq": "3GHz", "step": "500"},
        "output": {"sweepData": "sweepData"}
      }
    ],
    "dependencies": [...]
  },
  "contingency": {
    "plan": [
      {
        "step": 1,
        "action_id": "a1",
        "action_name": "频谱扫描",
        "tool_name": "sweep_frequency",
        "goal": "扫描目标频段",
        "contingency": [
          {
            "condition": "扫描无结果",
            "action_id": "a2",
            "action_name": "调整参数重扫"
          }
        ]
      }
    ]
  }
}

字段说明：
  actions (object)：动作脚本数据
    steps (array)：按执行顺序排列的动作步骤列表
      step_id (string)：步骤ID，格式 "{subject_id}-{序号}"
      subject_id (string)：执行主体（UAV agent ID）
      step_type (string)：步骤类型（工具名）
      step_name (string)：步骤名称
      input (object)：工具输入参数
      output (object)：工具输出结果
    dependencies (array)：步骤间依赖关系

  contingency (object)：异常应对数据
    plan (array)：每个动作的异常应对措施列表
      step (int)：对应动作步骤序号
      action_id (string)：动作ID
      action_name (string)：动作名称
      tool_name (string)：工具名称
      goal (string)：动作目标
      contingency (array)：该动作的异常应对措施
        condition (string)：触发条件
        action_id (string)：应对目标动作ID
        action_name (string)：应对目标动作名称

错误响应：
  HTTP 400：scenario 为空
    { "detail": "scenario 不能为空" }
  HTTP 422：请求体格式错误
    检查是否发送了 JSON 且字段名为 "scenario"
  HTTP 503：服务尚未初始化完成
    { "detail": "服务未就绪" }

注意：
  - 该接口为同步阻塞：会一直等到整个协同执行完成才返回，
    耗时取决于任务复杂度（可能几十秒到数分钟）。
  - 前端调用时应等待响应，期间可显示"执行中"加载状态。
  - 任务完成的标志：session_id 被轮换为新的值（如 42e516fe → 42e516fe-t1）。

------------------------------------------------------------
接口 2：健康检查
------------------------------------------------------------
GET /api/health

请求示例：
curl http://192.168.6.11:8000/api/health

响应（JSON，HTTP 200）：
{
  "status": "ok",
  "ready": true
}

字段说明：
  status (string)：服务状态，固定为 "ok"
  ready (boolean)：是否已就绪（true=可提交任务，false=仍在初始化）

------------------------------------------------------------
前端对接推荐流程
------------------------------------------------------------
1. 页面加载：GET /api/health 确认 ready=true
2. 用户输入任务：POST /api/run 提交 {scenario}
   → 等待响应（显示加载动画）
3. 拿到响应后直接使用 actions 和 contingency 数据进行展示
   - actions.steps：展示执行步骤列表
   - contingency.plan：展示异常应对方案
